接真实模型 · 操作指南

目标：把 MOCK 模型换成真实线上模型，验证语义层（参谋拟的方案到底能不能看）。 全程约 15 分钟，其中 10 分钟在等平台注册/充值审核。 代码一行都不用改——只填一个配置文件。

零、如果你不熟悉命令行：双击就行

项目里已经放好三个批处理文件，双击即可运行，不用学终端命令：

文件 作用 什么时候用
1_自检模型.bat 检查配置、连通性、JSON 输出 拿到 key 后先跑这个
2_跑验收测试.bat 跑 6 条验收用例 自检通过后
3_单条提问.bat 自己输入一个问题试试 想单独问一句时

双击后会弹出黑窗口，跑完显示"按任意键关闭窗口"，看完再关。

若想用命令行，在项目文件夹顶部地址栏里直接输入 powershell 并回车， 会弹出一个已经定位到当前目录的窗口，再粘贴命令即可。

一、拿 API Key（约 10 分钟）

推荐：DeepSeek 开放平台（便宜、OpenAI 兼容、注册即用）

步骤 做什么 地址
1 注册/登录（手机号即可） https://platform.deepseek.com
2 进入 API Keys 菜单 → 创建 API Key https://platform.deepseek.com/api_keys
3 立刻复制保存——密钥只显示这一次，关掉就没了 —
4 充值（新用户通常有赠送额度，够跑很多轮测试） 平台内「充值」

备选平台（都是 OpenAI 兼容，换 base_url + 模型名即可）

平台 控制台 适用
智谱 GLM https://bigmodel.cn 中文强，有免费额度模型
阿里云百炼 https://bailian.console.aliyun.com 企业常用，模型全
Moonshot Kimi https://platform.moonshot.cn 长文本
硅基流动 https://cloud.siliconflow.cn 一个 key 调多家模型

模型名一律以平台实际返回为准：填完 key 后跑 python check_llm.py --models，它会把你账号能用的模型全列出来，从里面挑。 别照抄网上的模型名——deepseek-chat 已在 2026-07-24 退役，本项目 .env.example 早期就写的这个名字，现已修正。

二、填配置文件（约 1 分钟）

在项目根目录执行（Git Bash）：

cp config/.env.example config/.env

或 PowerShell：

Copy-Item config\.env.example config\.env

然后用记事本/VSCode 打开 config/.env，改这三行：

LLM_BASE_URL=https://api.deepseek.com
LLM_API_KEY=sk-xxxxxxxxxxxxxxxx        ← 粘贴你刚复制的 key
LLM_MODEL_MAIN=deepseek-flash          ← 先用便宜的，够用就不加钱
LLM_MODEL_LIGHT=deepseek-flash

关于 base_url 带不带 /v1：如果自检报 404，把地址改成 https://api.deepseek.com/v1 再试。两种大多数平台都认，以自检通过为准。

安全：.env 只留本机。不要把 key 贴进聊天窗口、工单或提交到 git；泄露了去平台后台 Revoke 重新生成。

三、自检：先列模型，再验证（约 1 分钟）

python check_llm.py --models     # 第 1 步：列出你账号可用的真实模型名

从输出里选一个（带 ←主力 标记的是当前配置），把名字填回 .env。然后：

python check_llm.py              # 第 2 步：连通性 + JSON 输出实测

三步全绿才算通过：

检查项 不通过时怎么办
配置检查 key 为空 → 会降级 MOCK，不会真调用
连通性 key 错/余额为 0/base_url 不对 → 见脚本给出的提示
JSON 模式 该模型不支持结构化输出 → 换模型，这步不通全链路必挂

为什么非要验 JSON：本系统每个节点（路由、指挥、参谋、仲裁）都要求模型返回结构化 JSON，不是聊天文本。模型不支持 response_format=json_object，后面每一环都会解析失败。

⚠ 报「402 Insufficient Balance」怎么办

这是账户余额为 0，不是配置错了、也不是模型不行。两条路：

路线 1（推荐，0 成本）：换智谱 GLM —— Flash 系列永久免费

  1. 打开 https://bigmodel.cn ，手机号注册登录
  2. 进入控制台 → API Keys → 复制密钥
  3. 打开 config/.env：把 DeepSeek 那 4 行前面加 # 注释掉，把「备选 A：智谱」那 4 行的 # 去掉，粘贴新 key
  4. 再双击 1_自检模型.bat

路线 2：给 DeepSeek 充值（10 元够跑很久；一轮完整验收通常 1 元以内）

平台政策会变，各家的赠送额度以官网为准。拿不准就用 python check_llm.py --models 看账号到底能用哪些模型。

四、跑验收（约 2 分钟）

python run.py --test                        # 跑 6 条验收用例
python run.py "陆军现在多少人，多少装备？"     # 单条提问
python run.py "陆海空联合登陆作战，5天内完成投送，请做联合筹划"

看什么：输出的 [MOCK] 变成 [真实模型]，说明真的在调用了。

用例 期望
T1 陆军人数 答对 15900 人，终验 ✅
T2 写周报 拒答
T3 联合登陆 三参谋并行出方案 → 仲裁 → 终验 ✅
T4 海军兵力 答对 12500 人，终验 ✅
T5 需求不清 转人工澄清
T6 数字防篡改 拦下 → 回退重跑 → 最终答对

注意：T6 的故障注入只在 MOCK 分支生效（MOCK_FAULT 环境变量）。接真模型后它会自动跳过，这是正常的——数字防篡改的机器校验（HR-07）在真模型下依然全程生效，只是没法再人为注入一个错误数字来演示。

五、语义层质量怎么判（这一步才是重点）

链路跑通 ≠ 方案能用。真模型接入后，请按下面 6 条逐条看产物，而不是只看终端输出：

# 判据 怎么看 不达标的表现
1 数字仍 100% 来自 SQL 终验 ok=True；plans/*.json 里每个数字带 source: sql:q_xxx 终验报 FIGURE_MISMATCH，说明模型自己算了个数字
2 没有幻觉单位 方案里的 unit_id 必须能在兵力池里查到 终验报 HR-06 违规，出现库里不存在的番号
3 方案有实质内容 打开 plans/陆军.v1.json，看 timeline / risks 全是"按计划展开行动"这类空话，等于没规划
4 三个军种真的不一样 对比三份 plans/*.v1.json 三份像同一个模板套的，说明参谋没进入角色
5 约束被遵守 兵力不超上限、不进禁区、不超时限 终验列出具体违规项
6 稳定性 同一条用例跑 3 次 一次对两次错 = 不可用，需要调 prompt 或换更强模型

产物在哪：

plans/陆军.v1.json  海军.v1.json  空军.v1.json   ← 三个参谋各自的方案
plans/final_plan.v1.json                        ← 仲裁后的决心方案
trace/session_*.json                            ← 全流程记录（失败诊断靠它）

不达标时的诊断顺序（别一上来就说"模型不行"）：

  1. 先看 trace/ 里 route 判对没有 → 判错是意图层问题，改 src/graph/prompts.py
  2. 路由对但方案空 → 参谋简报不够自包含（忘了给兵力快照），改 STAFF_PLAN_* 模板
  3. 数字对不上 → HR-07 生效，模型在编数，加强 prompt 约束或在 validate 里加更严的校验
  4. 以上都对但质量差 → 才是模型能力问题，考虑升级到 deepseek-v4-pro

六、成本

场景 调用次数 大致花费
单域查询（"陆军多少人"） 2 次（路由轻量 + 参谋主力） 不到 1 分钱
全链路联合筹划 5 次（路由 + 指挥 + 三参谋 + 仲裁） 几分钱
一轮完整验收（6 用例） 约 20 次 通常 1 元以内

以官方实时计费为准。建议先设一个额度上限（平台后台可设），再跑批量测试，防止异常循环刷爆余额。

七、验证完之后

结论 下一步
6/6 通过且方案质量达标 第一期完成 → 开工二期：协商子循环（黑板书落盘 + 收敛判据）
链路通过但方案质量不行 按第五节诊断顺序调 prompt；确认是模型能力问题再升级模型
频繁解析失败/超时 查 src/llm/client.py 的重试与超时配置（LLM_TIMEOUT），必要时换更稳定的平台

一期的核心判据只有两条："陆军多少人"答得对 且 数字可追溯到 SQL。这两条过了，一期就算交付。
